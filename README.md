# Канбан на 3 месяца

Одностраничное приложение для личного планирования целей, проектов, задач и сроков.

## Возможности

- `index.html` — интерфейс приложения, стили и клиентский JavaScript.
- `api.php` — серверная авторизация и API хранения данных.
- Канбан-доска с недельной историей статусов и отдельной колонкой выполненного за выбранную неделю.
- Направления, проекты и задачи; задачи можно отправлять на канбан.
- Самостоятельные цели можно привязывать к проектам.
- Недельный светофор и заметки: одна случайная рекомендация, постоянные напоминания и пользовательские заметки.
- Дедлайны с календарём по месяцам и неделям, сортировкой по сроку и цветным приоритетом.
- Отчёт о выполненных задачах с CSV-выгрузкой.
- Печать канбан-доски и выбранного периода дедлайнов.
- Светлая и тёмная темы, адаптация под мобильные устройства и iPhone.

## Серверное хранение и вход

Данные канбана сохраняются на хостинге через PHP API, а не в `localStorage`. Все пользователи, вошедшие с одним паролем, видят одну общую доску. Сессия входа действует до закрытия браузерной сессии.

При первом входе приложение один раз переносит существующее состояние из `localStorage` этого браузера в серверное хранилище. После успешного переноса локальная копия удаляется. Последующие изменения записываются на сервер.

Для защиты создайте на хостинге файл `kanban-private/config.php`. Он содержит только хеш пароля и **не включается в публичный Git-репозиторий**. Для него в репозитории есть `.gitignore` и ограничение доступа через `kanban-private/.htaccess`.

Серверный JSON-файл автоматически создаётся PHP API в каталоге рядом с корневой папкой сайта, то есть вне публичного каталога сайта. Резервную копию данных периодически создавайте кнопкой «Экспорт».

## Ручная установка на REG.RU

В корневой каталог сайта загрузите и замените:

1. `index.html`
2. `api.php`
3. каталог `kanban-private/` вместе с файлами `.htaccess` и `index.php`

Отдельно создайте каталог `kanban-private` и загрузите в него полученный приватным способом файл `config.php`. Не загружайте его в GitHub и не публикуйте ссылку на него.

На хостинге должен быть включён PHP 7.3 или новее. Каталог на уровень выше корневой папки сайта должен быть доступен PHP для создания закрытого хранилища данных. API отклоняет входящие запросы по обычному HTTP: открывай сайт по HTTPS. При первой проверке откройте сайт по HTTPS, введите пароль и убедитесь, что доска загрузилась. После этого проверьте создание тестовой заметки, обновите страницу и убедитесь, что заметка осталась.

## Telegram-бот для изменений сайта

Поток: Telegram webhook → Cloudflare Worker → GitHub Actions workflow `telegram-codex.yml` → Python-агент на API Рег.облака → проверка → commit в `main` → reusable workflow `deploy-reg-ru.yml` → REG.RU → уведомление через Cloudflare Worker в Telegram.

В репозитории находятся `telegram-webhook.php`, `AGENTS.md`, `agent/telegram_site_agent.py` и `.github/workflows/telegram-codex.yml`. Агент обращается к OpenAI-совместимому API Рег.облака (`https://ai.reg.cloud/v1`), получает доступные модели через `/models` и отправляет задачу в `/chat/completions`.

Агент может полноценно менять прикладную часть приложения: `index.html` (интерфейс, разделы, стили и клиентскую логику) и `api.php` (прикладной API и серверное хранение). Поэтому разрешены не только косметические, но и функциональные изменения, новые разделы и расширение схемы пользовательских данных. Защищённые конфиги, секреты, аутентификация, Telegram-интеграция, Cloudflare и GitHub Actions остаются вне области изменений агента.

Изменения передаются точечными патчами с указанием файла. GitHub Actions проверяет список файлов, синтаксис JavaScript и PHP, затем коммитит оба прикладных файла и запускает публикацию на REG.RU. При изменении схемы данных агент обязан выполнять аддитивную миграцию. PHP API сохраняет неизвестные поля и разделы, не допускает отката версии схемы и создаёт резервную копию JSON перед повышением версии схемы. Существующие локальные данные браузера автоматически не удаляются.

### GitHub Actions secrets

В Settings → Secrets and variables → Actions должны быть настроены:

- `REGCLOUD_API_KEY` — API-ключ сервиса «ИИ-модели» Рег.облака;
- `TELEGRAM_GATEWAY_URL=https://zevnull-telegram-gateway.volt7459.workers.dev`;
- `TELEGRAM_GATEWAY_SECRET` — то же значение, что `GATEWAY_SHARED_SECRET` в Cloudflare;
- `TELEGRAM_BOT_TOKEN` — резервный маршрут прямой отправки уведомлений.

Существующие `REG_SFTP_HOST`, `REG_SFTP_PORT`, `REG_SFTP_USER` и `REG_SFTP_PASSWORD` используются повторно для публикации.

### Секреты Cloudflare и GitHub

Для Cloudflare Worker `zevnull-telegram-gateway` в Settings → Variables and Secrets должны быть настроены secrets:

- `TELEGRAM_BOT_TOKEN` — токен бота;
- `TELEGRAM_WEBHOOK_SECRET` — случайная строка для проверки Telegram webhook;
- `GITHUB_TOKEN` — Fine-grained token только для репозитория `zevnull00/kanban-goals` с Repository permissions → Actions: Read and write;
- `GATEWAY_SHARED_SECRET` — общий секрет для вызова endpoint `/notify` из GitHub Actions.

Variables Worker: `GITHUB_OWNER=zevnull00`, `GITHUB_REPO=kanban-goals`, `GITHUB_WORKFLOW=telegram-codex.yml`, `GITHUB_REF=main`, `TELEGRAM_ALLOWED_USER_IDS=848638447,663743323` и `ACCEPT_MESSAGES_AFTER`.

В GitHub → Settings → Secrets and variables → Actions должны быть заданы `REGCLOUD_API_KEY`, `TELEGRAM_GATEWAY_URL=https://zevnull-telegram-gateway.volt7459.workers.dev` и `TELEGRAM_GATEWAY_SECRET` (то же значение, что `GATEWAY_SHARED_SECRET`). `TELEGRAM_BOT_TOKEN` в GitHub оставлен как резервный маршрут отправки уведомлений.

Для первичной регистрации webhook используй файл `cloudflare/telegram-gateway/scripts/set-webhook.ps1` из PowerShell. Он запросит токен и webhook secret скрытым вводом, установит адрес `https://zevnull-telegram-gateway.volt7459.workers.dev/telegram` и покажет результат `getWebhookInfo`. Не регистрируй старый PHP endpoint вместо Worker, пока используется Cloudflare Gateway.

**Не помещай токены и секреты в GitHub-файлы, сообщения Telegram или код сайта.** Секреты хранятся только в Cloudflare Worker Secrets и GitHub Actions Secrets. Старый `telegram-webhook.php` оставлен в репозитории как резервный вариант и не удаляется.
## Разработка

Для локального запуска с серверным хранением нужен PHP и файл `kanban-private/config.php`. Простое открытие `index.html` как файла больше не поддерживает сохранение данных.

## Безопасность

- Репозиторий публичный: не помещайте в него пароли, хеши паролей, приватные ключи и персональные данные.
- Файл `kanban-private/config.php` исключён из Git.
- Пароль проверяется сервером через `password_verify`, браузер получает только результат проверки.
- Сессионная cookie имеет флаги Secure, HttpOnly и SameSite=Strict.
- Все, кто знает общий пароль, имеют доступ к общей доске. Это простой парольный барьер, а не система индивидуальных учётных записей.

## Последние изменения

- Пояснения доступны у карточек канбана через значок заметки; текст не раскрывается на самой доске.
- Пояснения задач проектов, задач направления и дедлайнов отображаются прямо в соответствующих списках.
- Задачи без проекта отображаются в своём направлении; отдельную задачу можно добавить прямо в направление.
- Задачу проекта можно перетащить мышью или передвинуть стрелками вверх/вниз. Стрелки также подходят для сенсорного экрана.
- Версия структуры экспортируемых данных — 4; импорт поддерживает старые версии 1–3.
