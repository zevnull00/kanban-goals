# Kanban goals

Автономное одностраничное приложение для планирования целей на 6 месяцев.

## Состав
- `index.html` — приложение (HTML, CSS и JavaScript в одном файле).
- Данные хранятся в `localStorage` браузера.
- Есть импорт и экспорт JSON; для переноса между устройствами используйте экспорт/импорт.
- Внешние библиотеки и CDN не требуются.

## Разработка
Откройте `index.html` в браузере или разместите его в корневой директории статического сайта.

## Ручная публикация на REG.RU через GitHub Actions
Workflow находится в `.github/workflows/deploy-reg-ru.yml`. Он запускается только вручную (Actions → Deploy to REG.RU → Run workflow) и загружает только `index.html`. Удалённые файлы не удаляются.

Перед запуском добавьте в Settings → Secrets and variables → Actions следующие Repository secrets:
- `REG_SFTP_HOST` — SFTP hostname или IP.
- `REG_SFTP_PORT` — обычно `22`.
- `REG_SFTP_USER` — отдельный SFTP-пользователь или основной логин хостинга.
- `REG_SFTP_PASSWORD` — новый пароль SFTP (не использовать пароль, ранее опубликованный в переписке).
- `REG_SFTP_KNOWN_HOSTS` — заранее проверенная запись SSH host key для этого хоста.

В поле `remote_path` при ручном запуске укажите абсолютный путь к целевой директории с точки зрения SFTP. Первый запуск рекомендуется направить в отдельную тестовую папку, например `kanban-preview`, а не поверх текущего сайта.

Workflow сначала загружает файл под временным именем, затем переименовывает прежний `index.html` в резервный файл и только после этого переключает новый файл на имя `index.html`. При ошибке переключения выполняется попытка восстановить резервную копию. Никакие другие удалённые файлы workflow не удаляет.

### Где взять host key
Получите SSH host key через доверенный канал REG.RU или с компьютера, на котором уже проверена подлинность сервера. Не используйте непроверенный результат `ssh-keyscan` как единственное доказательство подлинности сервера. Добавьте запись known_hosts в `REG_SFTP_KNOWN_HOSTS`.

## Безопасность
- Не добавляйте пароли, приватные ключи или содержимое `.env` в репозиторий.
- Репозиторий публичный: исходный код приложения доступен всем.
- Не храните личные данные в исходном коде. Пользовательские цели остаются в хранилище браузера.
